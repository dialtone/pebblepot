# 08: ✏️ Something else

**What to build:** Each section (Today's jobs, Kind things, Other jobs) has a ✏️ Something else button. It asks for a name, a picture, a pebble value (starting at 1) and who did it, then earns it in one step. A **Keep on the board** toggle starts on:
- **On:** the new item is created in that section, as a daily chore, good deed or occasional chore.
- **Off:** it's a one-off log entry with no item.

**Blocked by:** 04

**Status:** resolved

Spec: [Pebblepot v1](../../pebblepot-v1/spec.md)

- [x] Something else on each section creates the right kind of item when Keep on the board is on, and the new row appears on the board.
- [x] With Keep on the board off, only a log entry is written (with the given name, picture and value), and no row appears.
- [x] The pebble value defaults to 1.
- [x] The earn shows in the pot, the toast and the today list, and can be undone on the same day.
- [x] Covered by HTTP-seam tests.

## Comments

**2026-10-15, implemented** (PR build/ticket-08-something-else):
- **Rules.** New `rules::earn_something_else(store, now, tz, member, SomethingElse { kind, name, picture, value, keep_on_board })` runs in one immediate transaction. It checks the kind is a daily chore, occasional chore or good deed, the name isn't blank (new `Refusal::NameNeeded`, `name_needed`), the value is in `SOMETHING_ELSE_VALUES` (1 to 100, new `Refusal::BadValue`, `bad_value`) and the member is active. A blank picture becomes ✨ (`SOMETHING_ELSE_PICTURE`). Kept on the board, it inserts the item at the end of its kind (`MAX(position) + 1`) and writes an earn entry pointing at it; off, it writes an earn entry with `item_id` NULL. Either way the entry copies the name, picture and amount. A double-tapped "Give pebbles" is refused as `repeat_tap` when the same person earned something of the same name within `REPEAT_TAP_WINDOW` (2 s), so it never adds two rows. No migration was needed: `log_entry.item_id` was already nullable. The two new `Refusal` variants are appended at the end.
- **Read model.** Unchanged. A kept item is an ordinary `item` row, so `board::load` shows it with ✓s (chores) or badges (good deeds), and once-per-day and the good-deed repeat guard apply to later taps. One-off entries show up only in the today list.
- **Web.** Each section heading has a `✏️ Something else` pill (`data-something-else`) that loads `GET /something-else?section=<key>` (`SOMETHING_ELSE_PATH`) into `#sheet`. The sheet (`data-something-else-sheet`) has who-did-it radio faces (none picked, `required`), a picture field prefilled with ✨, a name field, a −/+ stepper on `value` (starts at 1, min 1, max 100) and a Keep on the board checkbox (checked). `POST /something-else` (form: `section`, `member`, `name`, `picture`, `value`, `keep`, plus the Other jobs search `q` via `hx-include="[data-search]"`) uses `hx-swap="none"`. On success it answers out of band with that section's rows (`#rows-<key>`, filtered by `q` for Other jobs), the pots, an empty `#sheet` (closing the sheet) and an earn toast with ↩︎ Undo. A refusal answers 200 with only the refusal toast, so the sheet stays open. An unknown section is 404, and a blank or garbled member or value turns into a refusal toast. Undo, the today list and live sync needed no changes: the write middleware bumps the version and `/board` redraws the new row on other devices.
- **Resolved ambiguities.** (1) Undoing a kept Something else removes only the log entry. The new row stays on the board, because undo is about the log; retiring it is edit mode's job (ticket 09). (2) The prototype's "Something else kind" sheet started at 2 pebbles; this ticket and starting-content.md say 1, so it starts at 1. (3) The spec doesn't cap the value; it is limited to 1 to 100 so a typo can't fill a pot, and 0 or negative is refused because pebbles are never taken away. (4) The picture is free text (the iPad's emoji keyboard), with ✨ as the default, as in the prototype's free-form good deed.
- **Tests:** `tests/something_else.rs`, 20 HTTP-seam tests (helpers are local to the file, `tests/common` is unchanged). They cover the button and sheet in every section (value 1, Keep on, nobody picked), a kept daily chore appearing at the end of its section with a ✓, each section creating its own kind, a new occasional chore following once-per-day and the search, a new good deed getting a badge and the repeat guard, one-offs from every section adding no row but showing in the today list with their own name, picture and amount, the default value of 1, the ✨ default, undo from the toast (row stays) and the today list, the next-day undo refusal across Rome midnight, the double-tap guard, blank name and out-of-range values, missing or unknown members, unknown sections, the search being kept, `/board` showing the new row, and a cross-site POST. 91 HTTP-seam tests in total, plus 6 unit tests. Mutation checks: Keep always on fails 3 tests, Keep always off fails 10, disabling the Something else repeat guard fails 1, a default of 2 fails 2, good deeds created as daily chores fails 3, no name check fails 1, and accepting any value ≥ 0 fails 1.
- **For ticket 09 (edit chores and deeds):** items added here are ordinary `item` rows (kind `daily_chore`, `occasional_chore` or `good_deed`), positioned at `MAX(position) + 1` within their kind, so they can be edited, reordered and retired like seeded ones. Their log entries already hold copies of name, picture and amount. `Section::from_key` and `Section::kind` in `src/web.rs` map a section key to its item kind, which a daily ⇄ occasional switch can reuse. `rules::SOMETHING_ELSE_VALUES` is a reasonable bound for edited values too. The section heading is now a `.section-head` wrapper (title plus the ✏️ pill), which is where an ✏️ Edit toggle or per-section controls could sit.
